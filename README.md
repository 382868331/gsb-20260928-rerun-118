# 应用资源调节系统（虚拟服务重放）

系统按观测、决策、执行三部分组织：

- internal/metrics：滚动窗口内的到达、完成、拒绝计数，以及等待时间统计。
- internal/decision：可插拔策略。首轮实现 QueueRateStrategy，同时依据队列高水位、平滑到达速率、估计所需工作者数做决策；每次决策都记录可读依据。
- internal/executor：虚拟时钟事件引擎，负责有界队列、准入拒绝、工作者启动延迟、忙碌者优雅退出和扩缩容冷却。
- main.go：重放“低流量 → 4 秒强突发 → 快速回落”的确定性流量。

## 关键规则

- 工作者进入容量后必须经过启动延迟，启动期间不能处理请求。
- 缩容先停空闲者；忙碌者标记为 draining，只完成手头在途工作，不再领取队列任务。
- 启动中仍有资源缺口时不反向缩容；扩容后需经过冷却期，并连续观察到低流量才允许缩容，避免震荡。
- 当所有在役工作者都忙且有界队列已满时，新请求被明确拒绝并计数；不静默丢弃请求。
- 重放结束校验：完成数 + 拒绝数 = 提交数，且不存在残留队列或在途工作。

## 运行

    go test ./...
    go run .

可调参数示例：

    go run . --min 2 --max 8 --queue 8 --startup 2s --tick 1s --cooldown 3s --seed 42
