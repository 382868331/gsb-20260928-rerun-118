# 应用资源调节系统（虚拟服务重放）

系统按观测、决策、执行三部分组织：

- internal/metrics：滚动窗口内各类别的到达、完成、拒绝计数与等待时间统计，账目按类别细分。
- internal/decision：可插拔策略。QueueRateStrategy 按类别依据队列高水位、平滑到达速率、估计所需工作者数决策，并显式扣除仍在启动延迟中的在途扩容；TotalQueueStrategy 是只看总队列长度的对照策略。每次决策都记录带类别的可读依据。
- internal/executor：虚拟时钟事件引擎，负责多类工作者、任务适配约束、分类有界队列、准入拒绝、工作者启动延迟、忙碌者优雅退出和分类冷却。

## 关键规则

- 每个任务声明类别，只能调度到具备对应能力的工作者上；未知类别立即明确拒绝。
- 工作者进入容量后必须经过该类别的启动延迟，启动期间不能处理请求。
- 扩容决策考虑启动延迟、分类队列水位与在途扩容，不只看总队列长度。
- 缩容先停该类别的空闲者；忙碌者标记为 draining，只完成手头在途工作，不再领取队列任务。
- 启动中仍有资源缺口时不反向缩容；每类独立冷却期，并连续观察到低流量才允许缩容，避免震荡。
- 当某类所有在役工作者都忙且该类有界队列已满时，新请求被明确拒绝并计数；不静默丢弃请求。
- 重放结束按类别校验：完成数 + 拒绝数 = 提交数，且不存在残留队列或在途工作。

## 重放与策略对比

main.go 生成确定性混合流量（同一随机种子可复现），覆盖三类场景：

1. short 类 4-8s 的短任务突发；
2. long 类全程的长任务占用；
3. long 类 10-14s 到达强度超过类别上限，必然产生容量达上限后的拒绝。

同一份流量依次用 queue-rate 与 total-queue 两个策略重放，输出各类别完成/等待/拒绝账目对比，
并把每个策略的非 hold 决策依据保存到 out/decisions-<策略>.log，用于解释重放差异。
